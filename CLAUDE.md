First run (no saved project) prompts for a **parent** folder and creates `<parent>/WEFT-MASTER`, persisting the path in a per-user config (`%APPDATA%/weft/config.json`, `~/.config/weft/config.json` elsewhere); later runs reopen it; if the folder went missing it offers to regenerate an **empty** project there. The graceful `SIGINT`/`SIGTERM` shutdown also removes the PID file. A bare positional is only treated as a one-off master path when it *looks* like one (`looksLikePath`: has a separator, a drive letter, or starts with `.`/`~`); an unknown first token (`weft close`'s old failure mode, `weft srve`, any typo) now errors with "Unknown command" instead of silently serving a nonexistent directory. `loadConfig` now normalises the stored `masterDir` through `resolveMasterPath` too, so a legacy pointer at a bare parent (e.g. the Desktop) can never be served as a project.

**Two config layers, don't conflate them:** the per-user `config.json` above is just a *pointer* to the active project (machine state, not project data). Each project's own `WEFT-MASTER/.weft/` lives **inside** the master folder so the project stays self-contained and portable — like `.git`/`.obsidian` in a repo/vault. `.weft/` holds the derived `graph.json` (disposable cache) **plus real user canvas state: `stickies.json` (graph annotations), `arrows.json` (roadmap arrows), `frames.json` (region frames — `{ marcos }`) and `layout.json` (saved needle positions)** — those four are not regenerable, do not treat them as caches. (A frame's `miembros` is the exception: **derived** from `layout.json` positions by containment on read, never stored.) Stickies and frames each carry an optional `fijado` boolean — pinned = locked in place on the canvas (drag pans instead of moving it). `IA-DOCS/WEFT_PLAN.md` remains the spec for data formats and the design language; **`IA-DOCS/BACKEND_PLAN.md` (Spanish, beginner-oriented) is the approved implementation plan for the backend.** Out of scope still: the spaced-repetition engine (the `.errorlog` read/write API, MCP resources and the timeline UI now exist; only the review-scheduling engine remains).

## What Weft is

A local-first learning tool ("AI harness to learn using AI"). A user starts a learning project and Weft renders its concept graph and content (lessons, examples, tests, challenges) in a browser. This first phase is a **web dashboard over the filesystem**: view the concept graph, open a concept, read markdown, take tests, and make the scoped edits the app already supports (notes, challenge solutions, new concepts, drawn relations). AI content generation happens through the MCP server (`weft mcp` — the AI reads the project and writes lessons/examples/tests/flashcards/errors via `master.ts`); the spaced-repetition engine is a later phase.

## Architecture

Single Node process (`weft serve`) serves the built frontend **and** the API. The browser cannot read the filesystem directly, so this minimal backend is required even though the app is "just a dashboard."

```
Browser (React)  ── fetch /api/* ──▶  Hono backend  ──reads──▶  WEFT-MASTER/ (filesystem)
  GraphScreen (needles + thread)
  ConceptScreen ([lecciones][ejemplos][tests][challenges])
```

Monorepo layout (npm workspaces): `server/` (Hono: `index.ts` startup + CLI, `api.ts` routes, `master.ts` filesystem layer, `graph.ts` graph regeneration, `mcp.ts` MCP server, `types.ts` mirror of the frontend types), `frontend/` (Vite + React: `screens/`, `components/`, `lib/`), and `bin/weft.js` (the CLI entry). The **top-level `WEFT-MASTER/` is the active project** the backend reads and develops against — use it directly (do not create the `fixtures/WEFT-MASTER/` from the plan; that idea is superseded). **`WEFT-MASTER/` is now git-ignored** (it's the user's working copy, not repo data); a fresh clone creates one with **`npm run seed`** (`scripts/seed.mjs` copies the committed **`examples/starter-master/`** — a clean 4-concept RAG roadmap — to `WEFT-MASTER/` only if absent). `npm run dev` runs both Vite (:5173) and the backend (:3131) together via `concurrently`; the frontend needs the backend up now that `httpApi` is the default.

**Repository layout (open-source).** The repo is set up for outside contributors: bilingual **`README.md`/`README.es.md`** and **`HOWTO.md`/`HOWTO.es.md`** at the root, **`LICENSE`** (MIT), **`CONTRIBUTING.md`**, **`CODE_OF_CONDUCT.md`** (Contributor Covenant), and **`.github/`** (issue + PR templates, a `ci.yml` that runs typecheck+build). The three internal Spanish design docs moved into **`IA-DOCS/`** (`WEFT_PLAN.md`, `BACKEND_PLAN.md`, `MCP.md`, + an `IA-DOCS/README.md` index) — reference them as `IA-DOCS/…`. **Packaging trap (don't reintroduce):** adding `.gitignore` makes npm fall back to it and would drop `dist/`, so the root `package.json` has a **`files` allowlist** (`bin`, `server/dist`, `frontend/dist`, `.claude/skills`) plus **`"prepack": "npm run build"`** — this is what keeps the built app **and** the bundled skill shipping while `WEFT-MASTER/`, `examples/`, `IA-DOCS/` and sources stay out of the tarball. Verify shipping with `npm pack --dry-run`.

Stack: TypeScript ESM (Node 20+), Hono + @hono/node-server, Vite + React, Tailwind, Cytoscape.js (`fcose` layout) for the graph, react-markdown + rehype, shiki/highlight.js for code, `motion` (motion/react) for UI animation, `cmdk` for the search palette. Distributed via npm (`npx weftjs serve`).

### API (reads + scoped writes)

Reads: `GET /api/health`, `/api/graph`, `/api/errors`, `/api/stickies`, `/api/arrows`, `/api/frames` (each frame with its derived `miembros`), `/api/layout`, `/api/concept/:id`, `/api/concept/:id/:folder/:file` (markdown text as `{ content }`), `/api/concept/:id/:folder/:file/raw` (raw bytes of a binary study document — a `.pdf` dropped in `lessons`/`examples` — streamed with its `Content-Type`; registered before the catch-all so the trailing `/raw` matches; 400 for a non-PDF or a traversal path), `/api/concept/:id/tests`, `/api/concept/:id/flashcards`, `/api/concept/:id/challenges/:file/solution`. Writes: `POST /api/concept/:id/notes`, `PUT /api/concept/:id/notes/:file`, `POST /api/concept/:id/challenges/:file/solution`, `POST /api/concepts`, `DELETE /api/concept/:id` (delete a concept **recoverably** — `master.deleteConcept` **moves the folder + all content into `.weft/trash/<id>`** with a manifest of the stripped incoming relations + positions, strips those now-dangling relations from the survivors' `.meta`, and prunes its `layout.json` position; `404` unknown), `POST /api/concept/:id/restore` (the inverse, used by Ctrl+Z — `master.restoreConcept` moves the trashed folder back to its original path, re-threads the incoming relations to survivors that still exist, restores the positions, and returns the `GraphNode`; `404` if nothing is trashed for that id), `POST /api/concept/:id/relations`, `DELETE /api/concept/:id/relations/:target` (idempotent inverse of add), `POST /api/concept/:id/errors`, `POST /api/stickies`, `PUT /api/stickies/:id`, `DELETE /api/stickies/:id`, `POST /api/arrows`, `PUT /api/arrows/:id`, `DELETE /api/arrows/:id` (roadmap-arrow annotations, `.weft/arrows.json`), `POST /api/frames`, `PUT /api/frames/:id`, `DELETE /api/frames/:id` (region frames, `.weft/frames.json`), `PUT /api/layout` (bulk `{ posiciones }`). Errors are uniform `{ error }` with semantic status (`404` unknown, `400` bad input incl. path traversal). `GET /api/errors` returns `{ errores: ResolvedError[] }` — every `.errorlog` entry across concepts, newest first, joined server-side (`master.getErrors`) with the solution that was given: the correct option + `explicacion` from `tests.json` for `fuente: 'test'`, the saved solution for `fuente: 'challenge'`. Checking test answers POSTs each miss to `/api/concept/:id/errors` (`fecha` filled server-side). Challenge solutions live in `challenges/.solutions/<file>` and never list as content.

## Core invariants (do not violate)

- **The filesystem is the source of truth.** No database. If the server dies, everything survives as `.md` and `.json` under `WEFT-MASTER/`.
- **`graph.json` is a derived cache**, regenerable from the per-concept `.meta` files. Never treat it as primary — `graph.ts` rewrites `.weft/graph.json` on every `GET /api/graph`.
- **Writes are scoped and go through the filesystem.** The HTTP write paths are few and explicit (note create/save, challenge solution, concept scaffold, add/remove relation, error-log append, sticky CRUD, layout save); each re-validates input and writes real `.md`/`.json` via atomic write. No database — a crash leaves plain files on disk.
- A concept is a folder; subconcepts are nested folders following the same recursive structure (`notes/ lessons/ examples/ challenges/` + `.meta .errorlog tests.json flashcard.json`).
- **`lessons/` and `examples/` also hold `.pdf` study documents** the user drops in (`listDocuments` lists `.md` + `.pdf`; `challenges/`/`notes/` stay markdown-only). The frontend `ReaderTab` renders a `.pdf` **in-app with PDF.js** (`pdfjs-dist`, a frontend dep): it fetches the bytes from the `…/raw` route and paints every page to `<canvas>` in a scrollable frame, plus a Download link. This is deliberate — an `<iframe>`/native viewer shows blank and offers a download on browsers set to "download PDFs" (common with the AV on this machine), so we render the pages ourselves. The PDF.js worker is wired via `import workerUrl from 'pdfjs-dist/build/pdf.worker.min.mjs?url'` → `GlobalWorkerOptions.workerSrc` (Vite emits it as an asset, served same-origin in prod). `.md` still fetches text + `MarkdownView`. Reading a PDF's text for AI generation (MCP) is out of scope — `getFile`/MCP file resources remain `.md`-only.

## Data model

See `IA-DOCS/WEFT_PLAN.md` for full JSON schemas. Key enums:
- `.meta` relation types: `requiere` (strong — solid thread), `relacionado_con` (weak — dashed thread).
- `.errorlog` entries: `{ errores: [{ fuente: 'test' | 'challenge', itemId, fecha, nota? }] }` — the learner's recorded mistakes, absent/empty ⇒ `{ errores: [] }`.
- **Schema extension (frontend, 2026-07):** each `graph.json` node carries a `resumen` string (1–2 sentence summary, derived from a `resumen` field in `.meta`), used by the graph hover card and search. The future backend must populate it when regenerating `graph.json`.
- **Schema change (2026-07): `.progress` removed.** Concepts no longer track `estado`/`dominio`; `graph.json` nodes carry no state and every needle renders identically. The `.errorlog` above is the replacement signal (and the seed for the future spaced-repetition engine). Any lingering `.progress` file is ignored.

## Design language — "bordado sobre lino" (embroidery on linen)

Non-negotiable identity. Screen = linen viewed from above; concepts = needle heads; edges = taut burgundy thread. Boldness is spent in one place, the graph; everything else stays still and disciplined.

- Palette (CSS tokens): `--linen #F2EDE4`, `--linen-raw #E8E1D4`, `--ink #2A2420`, `--muted #8B8177`, `--burgundy #7A2E3A` (the thread — the only saturated color), `--burgundy-deep #5C1F2A`, `--moss #3E6B54` (the quiet "correct / solved" affordance — test right-answers, a solved challenge; never a concept-state tint).
- Fonts: **Fraunces** (display/titles), **Inter** (body/UI), **JetBrains Mono** (code).
- Graph: needle-head nodes with subtle radial-gradient sheen and a single quiet neutral rim (all needles alike — concept state was removed), thread edges (solid for `requiere`, dashed for `relacionado_con`), labels always visible, one load animation (threads "tighten", time-bounded to ~1.1s so a large roadmap doesn't take ~9s to weave). Respect `prefers-reduced-motion`.

## Commands

Run from the repo root (npm workspaces):

- `npm install` — install all workspace deps. **This machine's HTTPS is intercepted by AV**: plain installs fail with `UNABLE_TO_VERIFY_LEAF_SIGNATURE`. Export the Windows root CAs to a PEM and pass `--cafile=<pem>` (and set `NODE_EXTRA_CA_CERTS=<pem>` for any Node-based downloader, e.g. Playwright's browser install).
- `npm run dev` — runs **both** servers via `concurrently`: Vite on http://localhost:5173 and the backend on http://localhost:3131 (the server's `dev` script passes `--master ../WEFT-MASTER`, so dev uses the seeded repo master and skips the first-run prompt). The frontend needs the backend up now that `httpApi` is the default; `VITE_API_MOCK=1 npm run dev:web` runs the frontend alone against the mock.
- `npm run build` — typecheck + production build of both workspaces (`frontend/dist/` + `server/dist/`).
- `npm run typecheck` — typecheck both workspaces.
- `npm run serve` / `node bin/weft.js` — production single process (requires a prior `npm run build`): serves the built app + API on :3131. With no `--master` it runs managed mode (first-run prompt / remembered location / regenerate-if-missing). Pass `--port N` / `--master PATH` to override. Installed globally (`npm link` / `npm install -g .`), the same entry is the `weft` command; subcommands: `weft path [dir]` (show/change the saved project location), `weft stop` / `weft close` (terminate a running production server and free its port, via the `%APPDATA%/weft/server.json` PID file), `weft skill install` (copy the bundled Claude Code skill into `~/.claude/skills/weft/`), `weft help`.

No test runner or linter is configured yet. End-to-end verification is done with Python Playwright scripts (see the webapp-testing skill pattern); a **dev-only** hook exposes the Cytoscape instance as `window.__cy` (absent in production builds — assert on the DOM/canvas there instead).

Dev-flake note: the first dev-server run after adding a new dependency may trigger a Vite dep re-optimization mid-session (full page reload) — re-run rather than chase phantom failures.
